# EfficientAI

Batch evaluation of student compression submissions with `eval.sh`.


## TLDR; How to run

```bash
uv sync --extra cuda129          # change cuda extra if your machine differs
# edit environment.sh, then:
source environment.sh
# put your row(s) in sample_entry.csv (one line per submission)
bash eval.sh sample_entry.csv
```


## Prerequisites

- Linux + GPU, with `uv`, `git`, and `curl` available
- Python deps from `pyproject.toml` (installed automatically via `uv sync`)
- A submissions CSV (default `weekX.csv`) with columns including `Name`, `Roll no.`, `GitHub URL`, `HuggingFace URL`
(this is just google sheet generated by google form downloaded as CSV)


## Required environment

Typical session setup (also see `exports.txt`; fill in your own token/webhook — never commit secrets):

```bash
export GITHUB_USERNAME=apd10

export SLACK_WEBHOOK_URL=https://hooks.slack.com/services/...
export DATASET=datasets/CS6013_sample_math_format_dataset

```

## Quick start

```bash
chmod +x eval.sh
bash eval.sh week4.csv week4.results.csv --interact --week 4
```

`--week` is required (also `WEEK=4`). It selects the expected `WeekNN` segment in GitHub paths and HuggingFace repo names. If any CSV row fails the naming check, eval aborts immediately and posts Slack; on success it Slack-notifies and continues.

Defaults when CSV/results paths are omitted:

| Input / output | Default |
|---|---|
| Submissions CSV | `weekX.csv` |
| Results CSV | `WeekNN.results.csv` (from `--week`) |
| Dataset | `datasets/CS6013_sample_math_format_dataset` unless `DATASET` is set |
| Limit | from `LIMIT` (default in script) |

```bash
./eval.sh --week 4 week4.csv week4.results.csv --interact
```

### Required naming

GitHub path (case-sensitive, two-digit `WeekNN` / `SubmissionNN`):

```text
https://github.com/<user>/CS6013/tree/<branch>/<roll_number>/Week<NN>/Compression_<target>/Submission<NN>/
```

Must match this tree:

```text
CS6013/
└── <roll_number>/
    └── Week01/                          # WeekNN from --week
        └── Compression_<target>/        # e.g. Compression_20
            └── Submission01/
                ├── compress.py
                ├── decompress.py
                ├── pyproject.toml
                ├── README.md
                ├── compression/
                │   └── __init__.py
                └── decompression/
                    └── __init__.py
```

HuggingFace:

```text
https://huggingface.co/<user>/<roll_number>-Week<NN>-Compression<target>-Submission<NN>
```

Examples: `…/22B1029-Week04-Compression40-Submission01` or `…/22B1256-Week04-Compression-20-Submission01`. Not `Compression_40`. GitHub `SubmissionNN` must equal the HuggingFace `SubmissionNN`.
## What each submission does

0. **Batch gate:** validate GitHub path + HuggingFace naming for `--week`; on any failure → Slack + abort (no eval)
1. Sparse-clone **only** the GitHub submission folder (`/tree/<branch>/<EnrollmentNo>/Week../Compression_../Submission../`); verify submission layout. The rest of `CS6013` is not downloaded.
2. Download the Hugging Face compressed checkpoint
3. Measure text size → `size_frac = compressed_text_GB / 8.0585`
4. Zero visual tensors in-place (`ensure_visual_zero.py`)
5. Create/sync a `.venv` from `pyproject.toml`
6. Run student `decompress.py`
7. Serve with vLLM on a free port
8. Run `evaluation/run_eval.py`
9. Append a row to the results CSV and post Slack
10. On **success**, stop vLLM and delete repo/model artifacts

Already-successful rolls (`status=ok` in the results CSV) are skipped on re-run.

## Modes

**Batch (default)** — process every CSV row; Slack on each result; on failure keep artifacts, wind down vLLM, continue.

```bash
./eval.sh --week 4
```

**Interact** — stop at the first failure; keep that run’s artifacts and leave vLLM up for debugging.

```bash
./eval.sh --week 4 --interact
# or: INTERACT=1 ./eval.sh --week 4
```

**Slack logs** — append Err/Error/Traceback greps from eval + vLLM logs to the Slack message.

```bash
./eval.sh --week 4 --slack_log
# or: SLACK_LOG=1 ./eval.sh --week 4
```

Flags can be combined:

```bash
./eval.sh --week 4 week4.csv week4.results.csv --interact --slack_log
```

## Useful environment overrides

```bash
DATASET=datasets/CS6013_sample_math_format_dataset                # eval dataset
CUDA_VISIBLE_DEVICES=2,3,4,6                         # GPUs for vLLM
MAX_NEW_TOKENS=32000                                 # generation budget (+ sets max-model-len)
LIMIT=30                                             # max examples
MAX_CONCURRENCY=30                                   # parallel requests to vLLM
CONFIG=configs/eval_config.yaml
WORK_ROOT=./eval_workdir
ORIGINAL_TEXT_GB=8.0585                              # denominator for size_frac
VLLM_READY_TIMEOUT_SEC=1800
```

Example:

```bash
# after sourcing exports / env above:
bash eval.sh week4.csv week4.results.csv --interact --week 4
```

## Outputs

| Path | Contents |
|---|---|
| `WeekX.results.csv` | Per-roll metrics: accuracy, `size_frac`, status, error, … |
| `outputs/<roll>_sample_math.json` | Full eval predictions |
| `logs/eval_<roll>.log` | Eval / pipeline stdout |
| `logs/vllm_<roll>.log` | vLLM server log |
| `eval_workdir/<roll>/` | Clone, compressed & decompressed models (kept on failure) |

## Resume behavior

- Skips rolls already `ok` in the results CSV
- Reuses existing sparse clone / download / decompress when present
- Reuses a live vLLM server only if it serves the same decompressed model path
- Failed clones do not leave a partial repo that pretends to succeed
- GitHub URLs without a submission subdir are rejected (no full-repo clone)

## Slack

Each run posts a two-line summary, e.g.:

```text
✅ Name (roll) | dataset | accuracy=… | size_frac=…
status=ok
```

```text
❌ Name (roll) | dataset | step=5_vllm | size_frac=…
step=5_vllm: reason…
```
